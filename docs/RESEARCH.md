# ریسرچ و تصمیم‌های معماری — کاشی (Kashi)

> نام موقت پروژه «کاشی» است (مثل کاشی‌کاری: قطعه‌های کوچک که کنار هم یک کل زیبا می‌سازند). قابل تغییر است.

## ۱. وضعیت فعلی بازار

| پروژه | نوع | نقطه‌ضعف |
|---|---|---|
| Farsi UI | کپی‌پیست به سبک shadcn (React + Tailwind + Radix) | فقط React، پکیج نصبی ندارد |
| Noor UI | کتابخانهٔ React با RTL-first | تمرکز روی عربی، پروژهٔ تک‌نفره و نوپا |
| persian-ui | پلاگین Tailwind | کامپوننت ندارد |
| کیت‌های Figma (Flowbite RTL و…) | فایل طراحی | کد ندارند |

**نتیجه:** هیچ دیزاین‌سیستم فارسیِ جاافتاده‌ای که هم چندفریم‌ورکی باشد، هم پکیج npm داشته باشد، هم سایت مستند خوب داشته باشد، وجود ندارد. این جای خالیِ واقعی است.

## ۲. فونت

**انتخاب: Vazirmatn (وزیرمتن)**
- لایسنس OFL (آزاد برای استفادهٔ تجاری)
- نسخهٔ Variable (وزن ۱۰۰ تا ۹۰۰ در یک فایل)
- نسخهٔ UI با ارتفاع کمتر برای هم‌خوانی بهتر با حروف لاتین
- نسخهٔ ارقام فارسی (FD)
- روی npm (`vazirmatn`) و jsDelivr موجود است

گزینه‌های بعدی برای اضافه کردن به‌عنوان فونت دوم/نمایشی: Estedad، Shabnam، Sahel (باید لایسنس هرکدام جدا بررسی شود).

## ۳. معماری چندفریم‌ورکی

سه لایه، از پایین به بالا:

```
@kashi-ui/tokens   ← رنگ، فاصله، فونت، سایه (JSON + CSS Variables + JS)
       ↓
@kashi-ui/css      ← استایل همهٔ کامپوننت‌ها با CSS خالص (کلاس‌های k-*)
       ↓                       ↓                          ↓
@kashi-ui/react    @kashi-ui/elements (Web Components)   HTML خالص / Vue / Svelte / Angular
```

- **چرا CSS خالص در هسته؟** هر فریم‌ورکی (حتی HTML ساده و وردپرس) می‌تواند از آن استفاده کند. ظاهر فقط یک‌بار نوشته می‌شود.
- **React** لایهٔ نازکی روی همان کلاس‌هاست (+ رفتارهای تعاملی).
- **Web Components** (مرحلهٔ بعد، احتمالاً با Lit) برای Vue/Svelte/Angular — React 19 هم از Custom Elements پشتیبانی کامل دارد.
- **CLI** (مرحلهٔ بعد): `npx kashi-ui init` و `npx kashi-ui add button` به سبک shadcn، برای کسانی که می‌خواهند کد کامپوننت را مستقیم در پروژهٔ خودشان داشته باشند.

## ۴. اصول طراحی

1. **RTL-first:** فقط از Logical Properties استفاده می‌کنیم (`margin-inline-start` به‌جای `margin-left`). به این ترتیب LTR هم خودکار کار می‌کند.
2. **Dark-first:** تم پیش‌فرض تیره، تم روشن با `data-theme="light"`.
3. **رنگ‌ها با هویت ایرانی:** فیروزه‌ای (اصلی)، لاجوردی، زعفرانی (هشدار)، اناری (خطر)، پسته‌ای (موفقیت).
4. **ارقام فارسی** به‌صورت پیش‌فرض در کامپوننت‌ها + ابزار تبدیل اعداد.
5. **دسترسی‌پذیری (a11y):** کنتراست AA، فوکوس قابل‌مشاهده، نقش‌های ARIA.
6. **رشد تدریجی:** هر کامپوننت جدا قابل نصب و نسخه‌بندی‌شده (semver + changesets).

## ۵. تصمیم‌های بعدی (به درخواست صاحب پروژه)

- **سبک بصری: در درجهٔ اول Untitled UI** (به درخواست صاحب پروژه، Untitled بر Polaris مقدم است): سطح‌های خنثی، سایهٔ اسکئومورفیک دکمه‌ها (حاشیهٔ داخلی + سایهٔ پایین)، حاشیهٔ داخلی سفید محوشونده روی دکمهٔ اصلی، حلقهٔ فوکوس نرم ۴ پیکسلی، آیکون شاخص با حلقه‌های هم‌مرکز در Alert، نشان‌های pill و نام‌گذاری توکن‌ها مثل `text-primary/secondary/tertiary`. از Polaris فقط ایدهٔ neutral-first و پیچ تراکم (density) مانده است.
- **سفارشی‌سازی در چهار لایه:** (۱) طیف `--k-brand-*` که با یک رنگ عوض می‌شود، (۲) پیچ‌های سراسری `--k-radius-factor` و `--k-density`، (۳) متغیرهای هر کامپوننت مثل `--k-btn-radius`، (۴) Cascade Layers تا CSS کاربر همیشه برنده باشد. تابع `createTheme()` همهٔ این‌ها را از چند ورودی می‌سازد.
- **دسترس‌پذیری WCAG 2.2 AA به‌عنوان شرط بیلد:** اسکریپت `contrast.mjs` همهٔ جفت‌رنگ‌ها را در هر دو تم بررسی می‌کند و در صورت رد شدن بیلد را متوقف می‌کند.
- **متن‌باز با لایسنس MIT.**

| مرحله | خروجی |
|---|---|
| **۱ ✓** | مونوریپو، توکن‌ها، CSS پایه، کامپوننت Button، صفحهٔ پیش‌نمایش |
| **۲ ✓** | Input، Textarea، Badge، Card، Alert، Avatar، AvatarGroup، Switch، Checkbox + تست‌های دسترس‌پذیری |
| **۳ ✓** | سایت مستندات تیره با Astro: صفحهٔ اصلی، ۵ راهنما، ۸ صفحهٔ کامپوننت، تم‌ساز زنده |

| ۵ | CLI (`npx kashi-ui add …`) |
| ۶ | Web Components برای Vue/Svelte/Angular |
| **۷ (بخش اول) ✓** | DatePicker و Calendar شمسی، کد ملی، شماره کارت، پکیج `@kashi-ui/persian` |
