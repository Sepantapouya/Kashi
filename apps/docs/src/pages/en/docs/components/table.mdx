## Tens of thousands of rows with virtual scrolling

With `virtual`, only the rows in view are rendered, plus a few above and below. Ten thousand or a hundred thousand rows scroll as smoothly as twenty. Sorting, selection and the sticky header work as before, and screen readers announce the total and each row's position through `aria-rowcount` and `aria-rowindex`.

<Demo html={false} code={`<DataTable
  caption="۱۰٬۰۰۰ سفارش"
  rows={orders}
  getRowId={(r) => r.id}
  columns={columns}
  virtual
  maxHeight="22rem"
/>`}>
  <VirtualTableDemo client:load />
</Demo>

- The table height comes from `maxHeight` (default 28rem).
- Rows must have equal height. The real row height is measured automatically; if your rows have a fixed height, pass it with `virtual={{ rowHeight: 48 }}`.
- Rows that are not rendered cannot be found with the browser's search (Ctrl+F). If users need to search all rows, put a search field above the table.
- For data that arrives from the server page by page, [pagination](/docs/components/pagination/) is usually simpler.

## Accessibility

- A real HTML table with a `<caption>` and `scope="col"` headers, so screen readers can move between cells.
- The sorted header has `aria-sort`, and sorting is done with a real button.
- Each row's checkbox gets its own name (`labels.selectRow`), such as "انتخاب تراکنش سارا احمدی" (Select transaction Sara Ahmadi).
- On narrow screens the table container scrolls horizontally and can be scrolled with the keyboard (Tab).
