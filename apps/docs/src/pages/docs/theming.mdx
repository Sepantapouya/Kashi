## تم‌ساز

تغییرات روی کل همین صفحه اعمال می‌شوند. کد تولیدشده را کپی کنید و در CSS پروژه بگذارید.

## چهار لایهٔ سفارشی‌سازی

### ۱. رنگ برند

همهٔ کامپوننت‌ها رنگ برند را از طیف `--k-brand-50` تا `--k-brand-950` می‌خوانند. تابع `createTheme()` این طیف را از یک رنگ می‌سازد:

```ts
import { createTheme } from "@kashi-ui/tokens";

const css = createTheme({ brand: "#7c3aed" });
// css را در یک تگ <style> یا فایل CSS قرار دهید
```

اگر طیف دقیق برندتان را دارید، آن را مستقیم بدهید:

```ts
createTheme({ brand: { 50: "#f5f3ff", 100: "#ede9fe", /* … */ 950: "#2e1065" } });
```

### ۲. پیچ‌های سراسری

| متغیر | پیش‌فرض | اثر |
|---|---|---|
| `--k-radius-factor` | `1` | ضریب همهٔ گوشه‌ها؛ `0` تیز، `2` بسیار گرد |
| `--k-density` | `1` | ضریب ارتفاع و فاصلهٔ داخلی کنترل‌ها؛ `0.875` فشرده |
| `--k-font-sans` | کاشی | فونت اصلی؛ راهنمای کامل در [فونت و تایپوگرافی](/docs/typography/) |
| `--k-text-scale` | `1` | ضریب اندازهٔ همهٔ متن‌ها |

### ۳. متغیرهای هر کامپوننت

هر کامپوننت متغیرهای عمومی با الگوی `--k-{کامپوننت}-{ویژگی}` دارد. فهرست کامل در صفحهٔ هر کامپوننت آمده است.

```css
:root {
  --k-btn-radius: 999px;      /* دکمه‌های کاملاً گرد */
  --k-input-height-md: 3rem;  /* فیلدهای بلندتر */
}

/* فقط در یک بخش خاص */
.checkout {
  --k-card-padding: 2rem;
}
```

### ۴. کلاس برای هر بخش داخلی

کامپوننت‌های چندبخشی `classNames` می‌پذیرند تا بدون دستکاری CSS کاشی، هر بخش را جدا استایل دهید (مثلاً با Tailwind):

```tsx
<Input
  label="ایمیل"
  classNames={{ label: "text-lg", box: "rounded-full", control: "font-mono" }}
/>
<DataTable classNames={{ row: "h-14", header: "uppercase" }} … />
```

همچنین ریشهٔ کامپوننت‌ها ویژگی‌های `data-variant`، `data-size`، `data-tone`، `data-state` و `data-placement` دارند:

```css
.k-btn[data-variant="primary"][data-size="lg"] { letter-spacing: 0; }
.k-input[data-state="invalid"] { background: var(--k-bg-error-subtle); }
```

### ۵. بازنویسی مستقیم

همهٔ استایل‌های کاشی در Cascade Layer با نام `kashi` قرار دارند. هر CSS معمولی شما، با هر میزان اختصاصی بودن، روی آن‌ها اولویت دارد:

```css
/* بدون !important کار می‌کند */
.k-btn { letter-spacing: 0; }
```

> **دام رایج: استایل‌های سراسری عناصر.** چون CSS شما همیشه بر کاشی اولویت دارد، قاعده‌ای مثل `a { color: blue }` رنگ دکمه‌ای را هم که با `<a class="k-btn">` ساخته شده عوض می‌کند. دو راه حل:
>
> ```css
> /* ۱. دکمه‌ها را مستثنا کنید و اختصاصی بودن را صفر نگه دارید */
> :where(a:not(.k-btn)) { color: blue; }
>
> /* ۲. یا ریست‌ها و استایل‌های پایهٔ خودتان را در لایه‌ای پیش از کاشی بگذارید */
> @layer my-reset, kashi;
> @layer my-reset { a { color: blue; } }
> ```

## تم روشن و تیره

تم پیش‌فرض تیره است. ویژگی `data-theme` را روی `<html>` یا هر عنصری بگذارید:

```html
<html data-theme="light">
<section data-theme="dark">…</section>
```

برای پیروی از تنظیم سیستم کاربر:

```js
const dark = matchMedia("(prefers-color-scheme: dark)").matches;
document.documentElement.dataset.theme = dark ? "dark" : "light";
```

> طیفی که `createTheme()` می‌سازد خودکار از نظر کنتراست بررسی نمی‌شود. پس از انتخاب رنگ برند، کنتراست دکمهٔ اصلی را بررسی کنید.

## کنتراست بالا

کاشی یک حالت کنتراست بالا برای هر دو تم دارد: همهٔ متن‌ها دست‌کم **۷ به ۱** (WCAG AAA)، حاشیهٔ کنترل‌ها دست‌کم **۴٫۵ به ۱**، و حلقهٔ فوکوس دوخطی که روی هر زمینه‌ای دیده می‌شود. این عددها در هر بیلد بررسی می‌شوند و اگر یکی کم شود، بیلد شکست می‌خورد.

اگر کاربر در سیستم‌عامل کنتراست بیشتر خواسته باشد (`prefers-contrast: more`)، این حالت خودکار روشن می‌شود. برای یک گزینهٔ «کنتراست بالا» در تنظیمات برنامه‌تان:

```html
<html data-theme="light" data-contrast="more">   <!-- همیشه کنتراست بالا -->
<html data-contrast="normal">                    <!-- حتی با تنظیم سیستم، عادی -->
```

`data-contrast` را روی `<html>` بگذارید. حالت رنگ اجباری ویندوز (`forced-colors`) جداست و کامپوننت‌ها در آن رنگ‌های سیستم را می‌گیرند.

## نقطه‌های شکست و لایه‌ها

نقطه‌های شکست همان مقادیر Tailwind‌اند، به‌اضافهٔ `xs`. متغیر CSS در `@media` کار نمی‌کند، پس این‌ها برای جاوااسکریپت و ابزارهای طراحی‌اند:

| نام | مقدار | پیکسل |
| --- | --- | --- |
| `xs` | `30rem` | ۴۸۰ |
| `sm` | `40rem` | ۶۴۰ |
| `md` | `48rem` | ۷۶۸ |
| `lg` | `64rem` | ۱۰۲۴ |
| `xl` | `80rem` | ۱۲۸۰ |
| `2xl` | `96rem` | ۱۵۳۶ |

```js
import { breakpoint, zIndex } from "@kashi-ui/tokens";

const wide = matchMedia(`(min-width: ${breakpoint.md})`).matches;
```

لایه‌ها (`--k-z-*`) ترتیب روی هم قرار گرفتن را ثابت می‌کنند تا منوی باز زیر سربرگ چسبان نرود: `base` ۰، `raised` ۱ (داخل یک کامپوننت)، `dropdown` ۱۰۰۰، `sticky` ۱۱۰۰، `overlay` ۱۳۰۰، `modal` ۱۴۰۰ و `toast` ۱۵۰۰. به‌جای عدد دستی از همین‌ها استفاده کنید: `z-index: var(--k-z-sticky)`.

## خروجی برای فیگما و ابزارهای طراحی

همهٔ توکن‌ها با قالب استاندارد [W3C Design Tokens](https://www.designtokens.org/) (نسخهٔ ۲۰۲۵.۱۰) هم منتشر می‌شوند، تا فیگما، Style Dictionary و Tokens Studio از همان منبعی بخوانند که کد کاشی:

| فایل | محتوا |
| --- | --- |
| `@kashi-ui/tokens/dtcg/kashi.tokens.json` | مقادیر پایه: رنگ‌ها، فاصله، گوشه، فونت، حرکت، لایه و نقطهٔ شکست |
| `…/dtcg/theme-dark.tokens.json` | توکن‌های معنایی تم تیره، با ارجاع به مقادیر پایه |
| `…/dtcg/theme-light.tokens.json` | تم روشن |
| `…/dtcg/theme-dark-contrast.tokens.json` و `theme-light-contrast` | دو تم با کنتراست بالا |

هر فایل تم کامل است، پس در فیگما یک مجموعهٔ «تم» با چهار حالت می‌سازد. با Style Dictionary:

```js
import StyleDictionary from "style-dictionary";

const sd = new StyleDictionary({
  source: [
    "node_modules/@kashi-ui/tokens/dist/dtcg/kashi.tokens.json",
    "node_modules/@kashi-ui/tokens/dist/dtcg/theme-light.tokens.json",
  ],
  platforms: { ios: { transformGroup: "ios-swift", buildPath: "build/", files: [{ destination: "Kashi.swift", format: "ios-swift/class.swift" }] } },
});
await sd.buildAllPlatforms();
```

گوشه‌ها و اندازهٔ متن با ضریب پیش‌فرض (۱) حساب شده‌اند.
