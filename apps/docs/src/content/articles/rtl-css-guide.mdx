اگر تا حالا سایتی را با `text-align: right` و چند `float: right` «راست‌چین» کرده‌اید، احتمالاً دیده‌اید که کار تمام نمی‌شود: فاصله‌ها برعکس است، فلش «بعدی» به عقب اشاره می‌کند، شماره تلفن به‌هم می‌ریزد و هر کامپوننت تازه دوباره همان دردسر را دارد. راست‌چین کردن درست یک ترفند نیست؛ چند قاعدهٔ ساده است که اگر از اول رعایت شوند، صفحه خودش درست می‌چیند.

این راهنما همان قاعده‌ها را به ترتیب می‌گوید: از تگ `html` شروع می‌کنیم و به آیکون‌ها و متن‌های دوجهته می‌رسیم.

## قدم اول: dir و lang روی html

مهم‌ترین خط کل کار همین است:

```html
<html lang="fa" dir="rtl">
```

`dir="rtl"` به مرورگر می‌گوید جهت پایهٔ سند راست‌به‌چپ است. با همین یک ویژگی، متن از راست شروع می‌شود، جدول‌ها از راست چیده می‌شوند، نوار اسکرول افقی سمت چپ می‌رود و `flex` و `grid` ترتیب را از راست حساب می‌کنند. `lang="fa"` هم به صفحه‌خوان، موتور جستجو و الگوریتم شکستن خط می‌گوید زبان صفحه فارسی است.

یک اشتباه رایج این است که به‌جای `dir` از CSS استفاده شود:

```css
/* نکنید */
body { direction: rtl; }
```

ویژگی `direction` در CSS فقط ظاهر را عوض می‌کند و معنای سند را نه؛ صفحه‌خوان‌ها و ابزارهای ترجمه آن را نمی‌بینند. جهت جزو محتواست، پس جایش در HTML است.

## ویژگی‌های منطقی به‌جای چپ و راست

ریشهٔ بیشتر مشکل‌های RTL، ویژگی‌های «فیزیکی» CSS است: `margin-left`، `padding-right`، `left: 0`، `border-right` و `text-align: left`. این‌ها به جهت صفحه کاری ندارند و در فارسی جای اشتباه می‌نشینند.

CSS برای هر کدام یک معادل «منطقی» دارد که بر اساس جهت نوشتن کار می‌کند. «ابتدا» (start) در فارسی یعنی راست و در انگلیسی یعنی چپ:

| فیزیکی (نکنید) | منطقی (بکنید) |
| --- | --- |
| `margin-left` | `margin-inline-start` |
| `padding-right` | `padding-inline-end` |
| `left: 0` | `inset-inline-start: 0` |
| `border-right` | `border-inline-end` |
| `text-align: right` | `text-align: start` |
| `width` / `height` | `inline-size` / `block-size` |

نتیجه این است که یک CSS واحد هم در فارسی درست است و هم در انگلیسی. اگر روزی بخواهید صفحه‌ای انگلیسی داخل سایت فارسی داشته باشید، کافی است `dir="ltr"` بدهید؛ چیزی برای بازنویسی نمی‌ماند.

```css
.card__icon {
  margin-inline-end: 0.75rem;   /* فاصله تا متن، در هر دو جهت درست */
  inset-inline-start: 1rem;     /* به‌جای left یا right */
}
```

همهٔ مرورگرهای امروزی این ویژگی‌ها را پشتیبانی می‌کنند، پس دلیلی برای ماندن روی `left` و `right` نیست.

## فلکس و گرید خودشان درست‌اند

`display: flex` و `display: grid` از قبل منطقی‌اند. در صفحهٔ `rtl`، اولین فرزند فلکس سمت راست می‌نشیند و `justify-content: flex-start` یعنی راست. پس لازم نیست برای فارسی `flex-direction: row-reverse` بنویسید؛ این کار در واقع ترتیب را دوباره برعکس می‌کند و صفحه‌خوان هم ترتیب را با ظاهر ناهماهنگ می‌بیند.

## آیکون‌های جهت‌دار

بیشتر آیکون‌ها جهت ندارند؛ ذره‌بین، قلب و سطل زباله در فارسی و انگلیسی یکی‌اند و نباید قرینه شوند. ولی چند آیکون معنایشان به جهت وابسته است:

- فلش‌های «بعدی» و «قبلی»
- شورون منوی کشویی که به سمت زیرمنو اشاره می‌کند
- آیکون «ارسال» و «خروج»

در صفحهٔ فارسی، «بعدی» یعنی چپ و «بازگشت» یعنی راست. ساده‌ترین راه این است که آیکون مناسب را انتخاب کنید، نه اینکه همه را با `transform: scaleX(-1)` قرینه کنید. اگر کامپوننت هم در فارسی و هم در انگلیسی استفاده می‌شود، فقط همان آیکون‌های جهت‌دار را با `:dir(rtl)` قرینه کنید. جزئیات بیشتر را در مقالهٔ [آیکون‌ها در رابط راست‌به‌چپ](/articles/rtl-icons-direction/) نوشته‌ایم.

```css
.icon--directional:dir(rtl) { transform: scaleX(-1); }
```

## متن دوجهته: شماره، ایمیل و کد

متن فارسی پر از تکه‌های چپ‌به‌راست است: ایمیل، شماره کارت، نام پکیج، نشانی سایت. مرورگر این تکه‌ها را با «الگوریتم دوجهتهٔ یونیکد» می‌چیند و گاهی نتیجه عجیب است؛ مثلاً `@kashi-ui/react` در وسط جملهٔ فارسی به‌شکل `kashi-ui/react@` دیده می‌شود.

راه درست، جدا کردن این تکه‌ها با تگ `bdi` یا ویژگی `dir` است:

```html
<p>پکیج <bdi>@kashi-ui/react</bdi> را نصب کنید.</p>
<input type="email" dir="ltr">
```

برای فیلدهایی که همیشه لاتین‌اند (ایمیل، نشانی سایت، شبا) `dir="ltr"` بگذارید، ولی برچسب و پیام خطایشان را فارسی و راست‌چین نگه دارید.

## یک فهرست بازبینی کوتاه

پیش از انتشار، این‌ها را چک کنید:

1. `lang="fa" dir="rtl"` روی `html` هست؟
2. در CSS هیچ `left`، `right`، `margin-left` یا `padding-right`ی نمانده که به جهت مربوط باشد؟ با جستجو در کد پیدایشان کنید.
3. `row-reverse` فقط برای دلیل واقعی استفاده شده، نه برای راست‌چین کردن؟
4. فقط آیکون‌های جهت‌دار قرینه شده‌اند؟
5. ایمیل، شماره کارت و کد در متن فارسی درست دیده می‌شوند؟
6. صفحه را یک بار با `dir="ltr"` باز کرده‌اید تا مطمئن شوید CSS به جهت وابسته نیست؟
