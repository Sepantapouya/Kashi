کاربر در جعبهٔ جستجو «كتاب» تایپ می‌کند و هیچ نتیجه‌ای نمی‌گیرد، در حالی که صدها «کتاب» در سایت هست. فرقشان؟ «ك» اول عربی است و دومی فارسی. از نظر کامپیوتر این‌ها دو حرف کاملاً متفاوت‌اند. جستجوی فارسی بدون یکسان‌سازی، بخش بزرگی از جستجوهای واقعی را از دست می‌دهد.

## چه چیزهایی باید یکسان شوند؟

<Figure n={1} alt="جدول جفت‌حرف‌هایی که شبیه‌اند ولی کد متفاوت دارند: ی و ي، ک و ك، ارقام فارسی و عربی، و نیم‌فاصله و فاصله" caption="جفت‌هایی که به چشم یکی‌اند ولی برای کامپیوتر نه؛ هر کدام دلیل رایجی برای «نتیجه‌ای پیدا نشد» است." />

- **«ی» و «ي»، «ک» و «ك».** صفحه‌کلیدهای عربی و بعضی صفحه‌کلیدهای قدیمی ویندوز و گوشی، شکل عربی را می‌زنند. متن‌هایی که از منابع قدیمی کپی شده‌اند هم پر از آن‌اند.
- **«ه» و «ة»، «ۀ»** و همزه‌ها: «خانهٔ» و «خانه‌ی» و «خانه».
- **نیم‌فاصله، فاصله و بدون فاصله:** «می‌خواهم»، «می خواهم» و «میخواهم».
- **ارقام فارسی، عربی و انگلیسی:** «۱۴۰۵»، «١٤٠٥» و «1405».
- **اعراب:** «کِتاب» و «کتاب».
- **نویسه‌های جهت نامرئی** مثل `U+200F` که در متن‌های کپی‌شده می‌مانند.

## تابع یکسان‌سازی

قاعدهٔ اصلی: **متن اصلی را عوض نکنید؛ فقط هنگام مقایسه، هر دو طرف را یکسان کنید.** متن نمایشی باید درست بماند (با «ی» فارسی و نیم‌فاصله)، ولی کلید جستجو یکسان‌شده باشد.

```js
function normalize(s) {
  return s
    .replace(/[يى]/g, "ی").replace(/ك/g, "ک")
    .replace(/[ۀة]/g, "ه").replace(/[أإآ]/g, "ا").replace(/ؤ/g, "و")
    .replace(/[ً-ٰٟ]/g, "")                 // اعراب
    .replace(/[۰-۹]/g, (d) => d.charCodeAt(0) - 0x06f0)    // ارقام فارسی
    .replace(/[٠-٩]/g, (d) => d.charCodeAt(0) - 0x0660)    // ارقام عربی
    .replace(/[‌‎‏\s]+/g, " ")              // نیم‌فاصله و فاصله
    .toLowerCase().trim();
}

normalize("كتاب‌هاي جديد") === normalize("کتاب های جدید"); // true
```

برای اینکه «میخواهم» (بدون هیچ فاصله) هم «می‌خواهم» را پیدا کند، می‌شود یک کلید دوم بدون فاصله هم ساخت و با هر دو مقایسه کرد.

## در پایگاه داده

یکسان‌سازی در مرورگر برای فهرست‌های کوچک (مثل فهرست شهرها یا [صفحهٔ مقاله‌های همین سایت](/articles/)) کافی است. برای جستجو در پایگاه داده:

- **یک ستون یکسان‌شده** کنار متن اصلی نگه دارید (مثلاً `title_search`) و هنگام ذخیره پرش کنید. جستجو روی این ستون انجام شود.
- **عبارت جستجوی کاربر** را هم با همان تابع یکسان کنید.
- در موتورهای جستجوی متن کامل مثل Elasticsearch یا Meilisearch، همین قاعده‌ها را به‌شکل «نرمال‌ساز» یا فیلتر کاراکتر تعریف کنید تا هم هنگام فهرست‌سازی و هم هنگام جستجو اعمال شوند.

## اشتباه چیدمان صفحه‌کلید

یک خطای رایج دیگر: کاربر فراموش کرده زبان صفحه‌کلید را عوض کند و به‌جای «سلام» تایپ کرده `sghl`. جستجوی خوب این را تشخیص می‌دهد و پیشنهاد می‌دهد:

<Figure n={3} alt="جعبهٔ جستجو با عبارت sghl و پیشنهاد آیا منظورتان سلام بود زیر آن" caption="وقتی متن انگلیسیِ بی‌معنی شبیه کلمه‌ای فارسی با چیدمان اشتباه است، به‌جای نتیجهٔ خالی پیشنهاد بدهید." />

```js
import { looksLikeWrongLayout, fixKeyboardLayout } from "@kashi-ui/persian";

looksLikeWrongLayout("sghl"); // true
fixKeyboardLayout("sghl");    // «سلام»
```

پیشنهاد بدهید، خودکار عوض نکنید؛ شاید کاربر واقعاً دنبال یک کد یا کلمهٔ انگلیسی بوده است.

## نکته‌های تجربهٔ کاربری

- **نتیجه‌ای پیدا نشد** را با پیشنهاد همراه کنید: فیلترها را بردارید، املای دیگری امتحان کنید، یا پرجستجوترین‌ها را نشان دهید.
- **قسمت پیداشده را برجسته کنید.** با یکسان‌سازی، جای کلمه در متن اصلی را باید با دقت پیدا کنید؛ ساده‌ترین راه، برجسته کردن کل کلمه است.
- **جستجو هنگام تایپ** با کمی تأخیر (۱۵۰ تا ۳۰۰ میلی‌ثانیه) تا با هر حرف درخواست نفرستید.
- **عبارت جستجو را در نشانی صفحه** نگه دارید (`?q=…`) تا قابل‌اشتراک و برگشت‌پذیر باشد.

## جمع‌بندی

متن فارسی را همان‌طور که درست است ذخیره کنید و فقط برای مقایسه یکسانش کنید: حروف عربی، نیم‌فاصله، ارقام و اعراب. اشتباه چیدمان صفحه‌کلید را تشخیص دهید و پیشنهاد بدهید. با همین چند خط، جستجوی سایت شما خیلی بیشتر از قبل پیدا می‌کند. توابع یکسان‌سازی و اصلاح متن در [ابزارهای فارسی کاشی](/docs/persian/utilities/) آماده‌اند.
