قیمت، حساس‌ترین عدد هر محصول است. یک صفر جابه‌جا یا یک واحد مبهم می‌تواند خرید را متوقف کند یا بدتر، به پرداخت اشتباه برسد. در این مقاله قاعده‌های نمایش و گرفتن مبلغ در رابط فارسی را مرور می‌کنیم.

## تومان یا ریال؟

واحد رسمی پول ایران ریال است، ولی مردم در زندگی روزمره با تومان (ده ریال) حساب می‌کنند. قاعدهٔ عملی:

- **در رابط کاربر، تومان** نشان دهید؛ چون کاربر با آن فکر می‌کند. «۱٬۲۵۰٬۰۰۰ تومان» را بلافاصله می‌فهمد.
- **در داده و API، یک واحد ثابت** نگه دارید و اسمش را در نام فیلد بیاورید، مثل `price_rial`. ابهام واحد در کد، منشأ باگ‌های گران است.
- **جایی که موضوع رسمی است** (فاکتور، رسید بانکی، قرارداد) و قانون یا درگاه ریال می‌خواهد، ریال بنویسید و اگر لازم است معادل تومان را هم کنارش بیاورید.

هرچه انتخاب کردید، واحد را **همیشه** کنار عدد بنویسید. عدد بی‌واحد در یک صفحه و ریالی در صفحهٔ بعد، کاربر را به اشتباه می‌اندازد.

## جداکننده و ارقام

برای عدد فارسی، رقم‌ها فارسی باشند و جداکنندهٔ هزارگان «٬» (جداکنندهٔ فارسی) باشد، نه ویرگول انگلیسی. جاوااسکریپت این کار را خودش انجام می‌دهد:

```js
(1250000).toLocaleString("fa-IR"); // «۱٬۲۵۰٬۰۰۰»
```

با `formatMoney` از `@kashi-ui/persian` واحد و تبدیل ریال به تومان هم یکجا انجام می‌شود:

```js
import { formatMoney } from "@kashi-ui/persian";

formatMoney(1250000);                    // «۱٬۲۵۰٬۰۰۰ تومان»
formatMoney(12500000, { from: "rial" }); // «۱٬۲۵۰٬۰۰۰ تومان»
formatMoney(1250000, { unit: "rial" });  // «۱۲٬۵۰۰٬۰۰۰ ریال»
formatMoney(2500000000, { compact: true }); // «۲٫۵ میلیارد تومان»
```

## قیمت‌های بزرگ: خلاصه ولی دقیق

«۲٬۵۰۰٬۰۰۰٬۰۰۰ تومان» درست است ولی خواندنش سخت است؛ چشم باید صفرها را بشمارد. در کارت‌ها و فهرست‌ها، شکل خلاصه («۲٫۵ میلیارد تومان») خواناتر است. ولی جایی که مبلغ دقیق مهم است، مثل صفحهٔ پرداخت و فاکتور، عدد کامل را نشان دهید.

## مبلغ به حروف

در فرم‌هایی که کاربر مبلغ را تایپ می‌کند (انتقال وجه، ثبت هزینه، پیشنهاد قیمت)، نمایش مبلغ به حروف زیر فیلد یکی از مؤثرترین راه‌های جلوگیری از اشتباه است. کاربر یک صفر اضافه را در «۱۲۵۰۰۰۰۰» نمی‌بیند، ولی «دوازده میلیون و پانصد هزار تومان» را فوراً تشخیص می‌دهد.

```js
import { numberToWords } from "@kashi-ui/persian";
numberToWords(2500000); // «دو میلیون و پانصد هزار»
```

## فیلد مبلغ خوب

<Figure n={3} alt="فیلد مبلغ با جداکنندهٔ خودکار هنگام تایپ، واحد تومان کنار فیلد و مبلغ به حروف زیر آن" caption="جداکنندهٔ خودکار، واحد ثابت و مبلغ به حروف؛ سه چیزی که اشتباه تایپی را تقریباً حذف می‌کنند." />

- **جداکنندهٔ خودکار هنگام تایپ:** کاربر «۱۲۵۰۰۰۰» تایپ می‌کند و «۱٬۲۵۰٬۰۰۰» می‌بیند.
- **پذیرش ارقام فارسی و انگلیسی** و حذف هر نویسهٔ دیگر.
- **واحد ثابت کنار فیلد**، نه داخل برچسب یا در جملهٔ راهنما.
- **مبلغ به حروف** زیر فیلد.
- **مقدار عددی خالص** برای ارسال به سرور، بدون جداکننده.
- **`inputmode="numeric"`** تا گوشی صفحه‌کلید عددی باز کند.

کامپوننت `PriceInput` کاشی همهٔ این‌ها را دارد و مقدار را به‌شکل عدد برمی‌گرداند:

```tsx
import { PriceInput } from "@kashi-ui/react";

<PriceInput label="مبلغ انتقال" value={amount} onValueChange={setAmount} />
// مبلغ به حروف به‌طور پیش‌فرض زیر فیلد نشان داده می‌شود
```

## تخفیف و قیمت قبلی

وقتی قیمت قبلی و تخفیف را نشان می‌دهید:

- قیمت قبلی را با خط‌خوردگی و رنگ کم‌رنگ‌تر بیاورید و قیمت نهایی را درشت‌تر.
- درصد تخفیف را گرد کنید («۲۰٪»، نه «۱۹٫۸۷٪»).
- خط‌خوردگی برای صفحه‌خوان معنایی ندارد؛ برای قیمت قبلی متن پنهان «قیمت قبلی» بگذارید تا صفحه‌خوان دو عدد پشت سر هم نخواند.

## جمع‌بندی

تومان را برای کاربر و یک واحد ثابت را برای داده انتخاب کنید، واحد را همیشه کنار عدد بنویسید، ارقام و جداکنندهٔ فارسی به کار ببرید و در فیلد مبلغ، به حروف نوشتن را فراموش نکنید. نمونه‌های بیشتر را در [صفحهٔ نمایش مبلغ](/docs/persian/money/) کاشی ببینید.
