کاربر ایرانی شماره موبایلش را با ارقام فارسی تایپ می‌کند: «۰۹۱۲…». کد شما با `Number()` یا یک عبارت باقاعده مثل `/^\d+$/` آن را بررسی می‌کند و نتیجه `NaN` یا «نامعتبر» است. این باگ ساده، یکی از رایج‌ترین دلیل‌های شکایت از فرم‌های ایرانی است.

## سه دسته رقم در یونیکد

<Figure n={1} alt="جدول سه ردیفی ارقام انگلیسی، فارسی و عربی با کد یونیکد هر کدام و تفاوت شکل ۴، ۵ و ۶" caption="ارقام فارسی و عربی نویسه‌های جدا هستند؛ شکل ۴، ۵ و ۶ هم در آن‌ها فرق دارد." />

| دسته | ارقام | بازهٔ یونیکد |
| --- | --- | --- |
| انگلیسی (لاتین) | 0123456789 | `U+0030` تا `U+0039` |
| فارسی | ۰۱۲۳۴۵۶۷۸۹ | `U+06F0` تا `U+06F9` |
| عربی | ٠١٢٣٤٥٦٧٨٩ | `U+0660` تا `U+0669` |

ارقام فارسی و عربی به چشم شبیه‌اند، ولی «۴»، «۵» و «۶» در آن‌ها شکل متفاوتی دارد و کدشان کاملاً جداست. کاربرانی که صفحه‌کلید عربی دارند یا از گوشی‌هایی با تنظیمات عربی استفاده می‌کنند، ارقام عربی می‌فرستند. پس هر ورودی عددی باید هر سه را بپذیرد.

## چرا Number و \d کار نمی‌کنند؟

```js
Number("۱۲۳");       // NaN
parseInt("۱۲۳");     // NaN
/^\d+$/.test("۱۲۳"); // false
```

در جاوااسکریپت `\d` فقط ارقام لاتین را می‌شناسد و `Number` هم همین‌طور. پس قبل از هر کار با عدد، ورودی را **یکسان** کنید.

## تبدیل به انگلیسی

ساده‌ترین روش، جایگزینی هر رقم با معادلش است:

```js
function toEnDigits(s) {
  return s
    .replace(/[۰-۹]/g, (d) => d.charCodeAt(0) - 0x06f0)
    .replace(/[٠-٩]/g, (d) => d.charCodeAt(0) - 0x0660);
}

Number(toEnDigits("۱۲۳")); // 123
```

برای فیلدهایی مثل موبایل و کارت که فقط رقم مهم است، بعد از تبدیل هر نویسهٔ غیرعددی را هم حذف کنید تا فاصله و خط تیره مزاحم نشوند:

```js
const onlyDigits = (s) => toEnDigits(s).replace(/\D/g, "");
onlyDigits("۰۹۱۲-۳۴۵ 67"); // "091234567"
```

## نمایش فارسی

برای نمایش عدد، از `Intl` استفاده کنید. هم رقم را فارسی می‌کند و هم جداکنندهٔ هزارگان و اعشار فارسی را می‌گذارد:

```js
(1234567).toLocaleString("fa-IR");    // «۱٬۲۳۴٬۵۶۷»
(3.75).toLocaleString("fa-IR");       // «۳٫۷۵»
new Intl.NumberFormat("fa-IR", { style: "percent" }).format(0.18); // «۱۸٪»
```

برای متنی که عدد را وسط خودش دارد (مثل «سفارش 123 ثبت شد»)، فقط رقم‌ها را جایگزین کنید:

```js
const toFaDigits = (s) => String(s).replace(/\d/g, (d) => "۰۱۲۳۴۵۶۷۸۹"[d]);
toFaDigits("سفارش 123 ثبت شد"); // «سفارش ۱۲۳ ثبت شد»
```

حواستان باشد این کار را روی کد، ایمیل، نشانی سایت و شمارهٔ نسخه انجام ندهید؛ «v2.1» یا «example123@mail.com» نباید فارسی شوند.

## کجا فارسی، کجا انگلیسی؟

<Figure n={3} alt="دو ستون: جاهایی که رقم فارسی مناسب است مثل قیمت و تاریخ، و جاهایی که رقم لاتین باید بماند مثل کد، ایمیل و شبا" caption="رقم فارسی برای محتوای خواندنی؛ رقم لاتین برای چیزهایی که کپی یا در جای دیگری وارد می‌شوند." />

- **فارسی:** قیمت، تاریخ، تعداد، درصد، شمارهٔ صفحه، هر عددی در متن فارسی.
- **لاتین:** کد و دستور برنامه‌نویسی، شبا و شماره کارت در جاهایی که کاربر کپی می‌کند، نشانی سایت و ایمیل، شمارهٔ نسخه.

یک نکتهٔ ظریف: در جدول‌ها و فهرست‌ها، رقم‌ها را یکدست نگه دارید. «۱۲ مورد» کنار «15 مورد» بیشتر از هر انتخاب دیگری آزاردهنده است.

## ارقام در فیلدها

- `type="number"` را برای کد ملی، موبایل یا کارت استفاده نکنید؛ صفر اول را حذف می‌کند و در بعضی مرورگرها ارقام فارسی را نمی‌پذیرد. `inputmode="numeric"` همان صفحه‌کلید عددی را باز می‌کند و مقدار را متن نگه می‌دارد.
- مقدار نمایشی فیلد را می‌شود فارسی کرد، ولی مقداری که به سرور می‌رود را انگلیسی بفرستید.

## راه کوتاه

همهٔ این توابع با تست‌های کامل در `@kashi-ui/persian` هستند:

```js
import { toFaDigits, toEnDigits, onlyDigits, formatNumber } from "@kashi-ui/persian";

toEnDigits("۱۲۳٤٥");          // "12345" (فارسی و عربی)
onlyDigits("۰۹۱۲-۳۴۵ 67");    // "091234567"
toFaDigits("Order 123");      // "Order ۱۲۳"
formatNumber(1234567);        // «۱٬۲۳۴٬۵۶۷»
```

و همهٔ فیلدهای عددی کاشی، از [کد ملی](/articles/national-id-validation/) تا [مبلغ](/articles/toman-price-formatting/)، هر سه نوع رقم را خودشان می‌پذیرند. فهرست کامل توابع در [ابزارهای فارسی](/docs/persian/utilities/) آمده است.
